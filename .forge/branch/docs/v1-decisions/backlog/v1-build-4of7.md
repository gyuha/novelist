# v1 구축 4-1/7 — 메모·주석

> 실행 주체: Paseo 역할 팀(오케스트레이터가 슬라이스를 역할별로 넘김). fg-run으로 실행하지 않는다. TDD는 backend 슬라이스(S2·S4)에 적용한다. 원래 4번(메모·주석·캐릭터)은 둘로 나눴다 — 캐릭터·참조 이미지는 `v1-build-4of7-characters`(작업 #8).

## 목표 / 범위 밖
- 목표: 소설·챕터·자유 메모(제목, 리치 텍스트 본문, AI 참고 표시, 소속 변경)와 전역 메모 화면, 챕터 본문 주석(마크로 텍스트를 따라가고, 위치를 잃으면 인용문과 함께 보존, 같은 마크가 돌아오면 재연결)을 만든다.
- 범위 밖: 캐릭터·참조 이미지(작업 #8), AI가 메모를 읽는 처리와 자유 메모의 컨텍스트 범위(5번), 메모 로컬 백업, 겹치는 주석, 비슷한 문장에 자동 재연결.

## 기준 문서
- 용어집: .forge/CONTEXT.md — 메모, 주석, AI 참고 메모, 챕터, 스냅샷
- 결정 문서: docs/v1-decisions.md (메모·주석·캐릭터)
- 관련 ADR: .forge/adr/261030-004647-tiptap-json-body.md
- 설계 근거: packages/db/SCHEMA.md(memos, annotations), design/DESIGN.md(메모·캐릭터 보조 화면, 메모·캐릭터 패널, 주석, 리더 뷰)
- 이번 그릴링에서 정한 것:
  - 분할: 4번을 4-1 메모·주석(이 계획)과 4-2 캐릭터·참조 이미지(작업 #8)로 나눈다
  - 주석 추가: 본문 선택 → 마크 적용 → **본문 저장과 주석 행 생성을 한 요청·한 트랜잭션으로** 처리(기존 버전 409 규칙 적용, 실패 시 둘 다 저장 안 됨). 주석을 추가하면 그때까지의 본문도 저장된다
  - 연결 상태 판정: 본문 저장·스냅샷 복원 때마다 서버가 그 챕터의 주석 행과 본문 마크를 대조 — 마크 있음 = 연결됨, 없음 = 위치 잃음(인용문 보존). 같은 id의 마크가 돌아오면 재연결(유사 문장 자동 재연결은 하지 않음)
  - 주석 삭제: 행 삭제 + 본문 마크 제거. 저장 시 서버는 행이 없는 주석 마크를 본문에서 제거
  - 겹치는 주석 금지: 이미 주석이 걸린 범위를 포함하는 선택에는 추가 불가(서버도 거부)
  - 문서 모델: `packages/shared`에 주석 마크(`annotation`, `id` 속성) 추가 — 챕터 본문은 허용, 메모 본문은 거부. `toPlainText`·내보내기는 주석을 출력하지 않음
  - 메모: 선택 입력 제목(최대 200자, 비면 목록에 본문 첫 줄 표시), 본문은 **챕터와 같은 문서 모델(문단·강조·장면 전환, 주석 제외)의 TipTap 리치 텍스트**, 본문 JSON 200KB 상한(초과 413), 소속(자유 ↔ 소설 ↔ 챕터) 변경 가능하며 변경마다 종류-소속 일치 재검증
  - 메모 저장: 명시적 저장 + 버전 불일치 409, 로컬 백업 없음
  - 삭제 연쇄: 챕터·소설 삭제 시 메모·주석 CASCADE 유지, 삭제 확인 창에 "메모 N개도 함께 삭제됩니다" 표시(개수 조회 API 제공)
  - 소유권: 다른 회원의 메모·주석은 404
